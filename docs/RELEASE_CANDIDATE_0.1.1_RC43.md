# 学序 StudyFlow 0.1.1-rc.43｜知到多视频本地采样诊断修复

## Windows 现场问题
知到同课程多个章节并行时，一部分任务有有效的本地视频进度条，另外的任务长时间显示「视频采样中断或一直没有有效数值」。部分情况可能是上游实际进入 pause / answering 阶段，而旧界面没有独立的阶段证据。

## 本轮变更
- 为每个子任务继续使用独立随机令牌与原子快照；额外解析 ZHS 控制台可信的 `playing`、`pause` 与 `answering` 阶段，并保留有效进度小数精度。
- 本地片段百分比**只**来自真实匹配的 `playing` 控制台行。暂停与处理题目输出中的百分比不是视频位置，故不显示为当前播放进度。
- 状态信息经 Python 队列、Rust 白名单验证和 React 同课并行卡片呈现；旧版无阶段字段的快照仍可安全读取。
- 改进对首次无采样、播放采样超时、暂停/处理题目、无效采样的区分。无有效数据时不插入虚构进度，不把运行状态当作服务器完成状态。
- 新增三路隔离、阶段变化、无效数值、时效检查和 UI 边界测试；原版 ZHS 执行器、发包与上游 vendored 代码不变。

## 验收与边界
- PR Python、React UI/IPC、Rust/Windows NSIS 构建及安装升级核验均通过才允许合并发布。
- CI 为本地观察器/安装包验证，不是本人知到账号下所有视频完成真实播放的证明。需 Windows 实机检查视频 A/B/C 是否各有独立、持续、与上游状态相符的观测。
- 若上游视频没有产生 `playing` 行、实际执行被阻塞或已退出，本工具不得自动增加进度。
- 服务端进度仍须只读核验，不能根据本机进度或退出码推断平台学习已完成。

版本：`0.1.1-rc.43`。
