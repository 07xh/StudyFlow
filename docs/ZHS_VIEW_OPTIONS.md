# 学序 ZHS 0.1.5 原版任务观看控制

新功能借鉴雨课堂设置页的保存/校验/进程监督模式，但沿用原 ZHS 0.1.5 心跳发送与视频处理实现。

| 选项 | 当前链路 | 条件 |
|---|---|---|
| 倍速 | 官方 `--speed` | 1–2× |
| 实际倍速上限 | 学序任务启动前限制原版基准倍速 | 共享课考虑上游 ±0.15× 波动，AI 不波动 |
| 单次时间限制 | 官方 `--limit` + 学序执行进程上限 | 0 继承原版设置；1–1440 分钟，包含启动耗时 |
| 最多处理视频 | 只调度首 N 个未完成目标或 AI 视频调用 | 0 不限制；1–1000 |
| 指定章节 / 视频 | 学序过滤原版实时课程上下文 | 必须先同步当前账号已核验课程明细；最多 256 个项目 |
| AI 知识点选择 | 学序过滤原版的知识点迭代器 | 选择的知识点 ID 须属于实时上下文 |
| 异常时停止 | 仅改变调用是否继续，保留原版错误响应与心跳算法 | 可选 |
| 已完成跳过 | 由 ZHS 原版完成状态决定 | 不提供无法生效的反向开关 |
| AI 选学资源 | 官方 `--learn-optional` | 仅 AI |
| 同课章节并行 | 以实时课程目录的章节为独立运行路数，同章资源顺序执行 | 1–3 路，新配置默认 2；旧配置迁移为 1；只有一个待执行章节则实际只有 1 路 |
| 心跳发送频率 | 继续由现有 ZHS 执行实现负责 | 不新增发送频率入口 |

每门课的配置独立保存在 `%LOCALAPPDATA%/StudyFlow/zhidao/zhs-course-settings/<课程哈希>.json`；未设置时继承全局 `%LOCALAPPDATA%/StudyFlow/zhidao/zhs-task-settings.json`。旧三字段配置按原值迁移。课程范围偏好按课程 ID 保存到学序 UI 本地存储，不含 Cookie。

章节并行设置位于当前课程的「ZHS 原版 · 观看控制」中。选择 2 或 3 后，优先启动不同章节的第一个未完成资源；同一个章节中的视频、文章、PPT 严格按原顺序一个接一个执行。章节边界直接取实时课程目录（共享课 chapter；AI 课 cake theme），不从标题数字猜测。每个资源仍使用独立进程、实时范围与采样令牌；AI 按知识点 + 资源 UID 精确拆分。同一平台仍只允许一门课运行。未知章节成员统一归入保守的单队列。运行区按章节展示进度、等待队列、本轮记录和「停止此项」；原有「停止」回收整个课程的进程树。跨章节并发不等于平台已确认并行记账。

普通视频失败按「异常时停止」选项决定是否继续，验证码、平台时间限制和登录失效等明确阻断条件停止整个队列。已退出视频不保留实时百分比；本地片段位置、进程退出和服务端核验分别表达。该功能的真实账号并发记账兼容性仍待实测。

任务目标来自现有只读服务器核验快照的真实 `videoId`、`knowledgeId`；运行前在原版的最新课程上下文中验证 ID。一旦旧范围不能对应新的课程结构，拒绝任务，不降级为全课程操作。

代码通过 Python 专用 sidecar 进程中的可恢复遍历包装实现，不修改已安装 ZHS 0.1.5 包、心跳编码、发送器、上报端点或原版 `~/.zhs/config.toml`。
达到视频计数或任务运行时间上限会返回独立状态 12；普通视频错误触发按配置停止返回 13；失效的指定范围返回 14。上述状态 **都不是服务器已确认完成**。

CI 只能确认选项约束、离线调度与安装流程；仍必须进行 Windows 真机账号与服务端只读进度核验。
