# 学序 StudyFlow 0.1.1-rc.19｜雨课堂服务器完成状态与单节进度修复

## 本次修复（PR #108）
- 雨课堂：修复服务器视频观看率（例如 98.1%）与服务器明确的完成状态不同步时，章节被错误划入“待完成”的情况。服务端存在明确且合法的 `completed` 完成标志时优先以其判断，原始观看百分比仍独立保留、不改写为 100%。
- 课程章节：对“已完成但观看率小于 100%”显示“服务器已确认完成 · 原始观看进度 98.1%（口径不同）”，统计正确归入已完成。
- 单节核验：章节内新增“只复核此节”，以已枚举的视频 ID 和精确页位置只读查询，不需为了一个异常视频重新核验全部课程。
- 播放结束后：对唯一匹配的单视频允许有限时长、最多三次有间隔的只读进度补查，以覆盖服务端确认延迟；不会因此反复扫描整门课。
- 进度读取：为只读查询补充禁用中间缓存的请求头，避免中间缓存重复响应。
- 自动化回归：新增 98.1% 与服务器完成标志冲突、同名视频、单节复核、客户端状态展示及原始进度不伪造等测试。

## 保留功能
- 延续 rc.18 的雨课堂首次全课核验、跨页面共享缓存、顶部/课程卡片进度汇总、知到与雨课堂的播放/任务/恢复机制及更新说明窗口。
- 不修改原版雨课堂的学习事件或服务端写入机制，不以本机播放到末尾、日志文本、可配置阈值取代服务器完成确认。

## 限制与验收
- **真实平台校验**：用户反馈该视频已从雨课堂待完成任务中消失；这并不证明其当前接口响应一定含 `completed` 字段。需要在真实 Windows + 雨课堂账号复核该字段及 UI，若接口未提供明确完成证据，页面仍应如实显示服务器返回的观看率与未确认状态。
- **构建发布门禁**：仅当合并后的最新 main 完成 Python/React UI/IPC、Windows NSIS、干净安装/升级/启动/卸载测试后，才发布独立的 v0.1.1-rc.19 候选安装包；不能覆盖旧版本或将 PR 构建 artifact 误称为发布版。
- 不以离线 CI 代替真实账号的课程完成状态核对。
