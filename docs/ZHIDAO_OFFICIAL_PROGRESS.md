# 知到真实课程进度对齐（2026-11-15）

## 问题
官方知到 App 的课程进度约 4%，而 StudyFlow 原先显示 4/147 = 2.7%。原进度来自已达到 100% 的知识点数量占比，不是知到官方课程总进度。掌握度属于另一指标。

## 数据源与语义
- 复用现有 **只读** `queryStudentAICourseList` 返回的 `schedule`（课程进度百分比），与独立的 `mastery`（掌握度）区分。
- 公开的第三方课程总览协议记录了这两个字段：`eplayn/zhihuishu-toolkit` 的 `docs/05-课程总览协议.md`，需用真实账户校验适配版本。
- 只接受数值类型、有限、0–100 的 `schedule`；不将缺失字段、异常值、知识点完成数猜测成官方进度。
- 为每个官方进度值附真实读取时间，并使用本机会话校验标识归属；旧响应不能覆盖更晚的同会话核验。
- 单课只读核验重新访问课程列表获得最新的 `schedule`，并保留现有知识点明细读取。
- 当当前账户/API 不提供可验证的 `schedule` 时，**明确标注**“满进度知识点占比”；不静默冒充官方课程总进度。
- 原版 ZHS 心跳、播放进度上报、资源完成行为不修改。

## 待 Windows 真机核验
1. 以知到 App“进度”与学序“知到课程进度（schedule）”对比同一账号、课程和教学班。
2. 退出再登录、关闭再打开学序，等待自动只读核验后确认新旧数值与时间戳。
3. 核验课程列表返回字段缺失、服务器异常、窗口焦点切换、同一课程连续刷新与切换其他账号时不出现伪进度。
4. 若 App 进度与 `schedule` 仍不同，保留两种来源及原始校验时间，不强行匹配数字；根据实际脱敏响应确认是否存在版本差异。
