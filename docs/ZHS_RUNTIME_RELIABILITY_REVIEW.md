# ZHS 运行可靠性与学序进度证据审查

> 2026-11-15 · 对象：StudyFlow 的知到运行层。该文档只审查任务管理、进度观测和验证，不修改 ZHS 0.1.5 原版协议、计时或上报算法。

## 1. 三个独立证据

| 证据 | 来源 | 可以证明 | 不能证明 |
|---|---|---|---|
| 原版 CLI 本地片段 | ZHS 标准输出只读监控 | 当前任务在本机输出了进度片段 | 服务端已记账或任务完成 |
| 进程状态与退出码 | Tauri Rust 托管子进程 | 是否成功创建进程、进程是否退出 | 平台接受学习记录 |
| 服务器课程进度 | 学序的当前账号、当前课程只读核验 | 对应时间点服务器返回的课程数据 | 本地任务在此后是否仍在运行 |

禁止将任何单项证据自动提升为“已完成”。本地输出过期时，必须隐藏实时数值并显示过期状态；已退出仅能展示最后一次有效采样。

## 2. 已保留的源代码与运行路径

- 上游固定为 `pjm314159/zhs@v0.1.5`，不修改原始心跳/进度发送行为。
- 共享课走原有 ZHS `play` 路径，AI 智慧课程走原有 ZHS CLI。
- Windows sidecar 用原版 CLI 并保留兼容回退；前端不另起网络请求执行器。
- Rust 一个平台只管理一个已启动的任务，停止时回收学序自己创建的进程树，不终止其他窗口的原版工具。
- `ZHS-ConsoleMonitor.py` 只提取合法数值快照；监控令牌、有效时间窗和字节上限由 Rust 二次校验。

## 3. 可靠性修复

- 修复 `legacy_stop` 空闲返回缺少 `zhs_stale` 导致的 Rust 结构体初始化缺陷。
- 只展示当前平台下有 `server_verified` 证据、有效百分比和核验时间的课程记录。不会混入其他平台的课程。
- 知到课程标题按平台和课程键匹配，避免跨平台 ID 相同导致误标。
- UI 用递增请求序号丢弃过期轮询响应，防止较慢的旧请求覆盖新的任务状态；组件切换平台时重置前一平台状态。
- 已核验进度保留时间戳提示，界面继续保持紧凑，不增加重复模块。
- Python、Node 和 Rust 契约测试共同保护原版路径及证据边界。

## 4. 其他开源实现的取舍

- [Autovisor](https://github.com/CXRunfree/Autovisor)：浏览器真实播放状态、页面加载超时和课程切换的工程设计可参考；不适合作为 ZHS 0.1.5 原生协议的直接替换。
- [point-zip/fuck-zhs](https://github.com/point-zip/fuck-zhs)：有持久化任务与双驱动管理思路，但其基于时间戳的协调不等于强互斥，且本地目标位置不一定证明服务端完成；不移植模拟上报实现。
- [university-helper](https://github.com/sweetcornna/university-helper)：任务 ID、状态查询与健康检查可参考；不额外引入服务端执行器。
- [zhihuishu-tool](https://github.com/luoyily/zhihuishu-tool)：已归档，适合作历史接口研究，不作生产依赖。

## 5. 回归验收边界

1. **自动化静态与单测**：Python 原版文件锁定、监控输入过滤、错误/退出语义、React 任务视图、Rust 状态序列化。
2. **Windows CI**：编译 Rust/Tauri、运行前端及 Python 测试，生成 NSIS 安装包并检验包内原版依赖。
3. **Windows 干净环境**：安装、启动与停止、后台子进程回收、原版内置/回退来源、网络断开及重新登录后的状态刷新。
4. **真实账号只读核验**：当前账号、课程、时间戳一致；服务端未返回确认时显示“尚未核验”，不得用 CLI 退出码或本地 100% 代替。

CI 通过不等于 Windows 本人账号实测通过；打包成功不等于服务器认可学习记录。保留现有 ZHS 原版发送逻辑，今后仅在有明确真实兼容证据和授权范围内评估协议变更。

## 6. 2026-11-15 新增构建期隔离补丁

历史章节记录的是只读观测阶段。后续构建增加经过源文件哈希锁定的 ZHS 0.1.5 发送可靠性补丁，修复 AI、Hike、共享课程的错误处理与退出条件。Windows 打包使用修改后的隔离 ZHS 副本，而 legacy 原始快照与用户已安装的 ZHSDesktop 不修改。更多说明见 docs/ZHS_UPSTREAM_SENDER_RELIABILITY.md。
