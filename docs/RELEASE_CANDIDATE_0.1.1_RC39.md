# 学序 StudyFlow 0.1.1-rc.39｜LightC 风格启动动画

## 本次更新
- Windows 学序主窗口增加轻量品牌启动画面。HTML 首帧即显示学序标识与低饱和度双光晕，不再先显示空白 React 容器。
- 启动屏继承应用已保存的浅色、深色或跟随系统设置，优先展示主题正确的第一帧。
- 采用单 WebView 启动画面，没有第二个窗口、视频解码或额外的动画框架；支持系统减少动态效果设置。
- 每次完整启动显示动画：正常启动最短约 520 毫秒，首次声明检查就绪后约 180 毫秒淡出；初始化更久时立即淡出，不再额外等待固定动画时长。后台连接状态检查和课程同步继续按原逻辑运行，不阻挡首页。
- 3.2 秒后仅当 React 主界面已经挂载才提供“进入学序”按钮，防止跳过后空白；12 秒后根据实际界面状态提示慢启动或重新打开。无伪造进度百分比。首次使用声明和本地文档读取共用 8 秒总时限，超时显示可重试错误界面，迟到的旧结果不会覆盖新请求。
- 增补前端启动屏回归测试，检查静态首帧、主题匹配、幂等退出、冷启动就绪即退、减少动态效果、React 未挂载保护及旧请求防护。
- 继续使用仓库已有的 PR 构建和回归检查；主分支发布策略保持不变。

## 同版 U校园扫码修复
- “打开二维码登录”改为独立内置窗口，直接显示 Unipus 官方 SSO 扫码页，而不是原来进入 U校园AI首页；同时保留图片/数字验证码账号登录和系统浏览器扫码备用入口。
- Windows WebView2 的登录窗口构建、复用与关闭、Cookie 导入后清理改在后台阻塞线程执行，避免同步操作占用主 UI/IPC 线程；不会自动识别或绕过验证码。
- 扫码后仍必须核验是否取得 U校园AI JWT，空课程或单纯扫码成功不算已登录。窗口出现二维码但未回传 JWT 时，保留本人 Cookie 手动导入。
- 旧版窗口的卡死/闪退尚无用户设备崩溃日志；上述是针对可确认代码路径的修复，仍需实机复现确认。
  
## 继承功能
- 完整保留 rc.38 的 U校园官方登录窗口、有效期提示、会话清理及其他更新。
- 不改变知到、雨课堂、学习通的业务逻辑；U校园仅调整官方登录窗口、扫码入口和会话读取前后的安全交互，不修改课程/进度接口或心跳实现。
- 保留用户已有数据和 Windows 凭据，不迁移数据库、不改登录态。

## 验收说明
- 只有 GitHub Actions 的正式 Windows 构建、安装升级检查及 GitHub Release 全部成功，才视为已发布。
- CI 的前端测试不等于已完成用户设备的视觉、性能与冷启动测试。仍需在 Windows 真机验证深浅色首帧、首次同意声明、异常重试和热启动。
- 启动画面只覆盖 WebView 开始渲染之后的加载时间，不能代替 Windows 原生进程初始化耗时分析。
