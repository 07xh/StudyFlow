# 学序 StudyFlow 0.1.1-rc.20｜雨课堂严格完成判定与任务状态澄清

## 本次更新（合并 PR #112）
- 修复雨课堂原版旧配置默认采用 90% 本地完成阈值，可能导致课程实际上尚未完成却提前跳过或结束的情况。
- 学序在启动雨课堂任务时，将本次执行的完成阈值统一为 100%；即使保存的是旧版 90% 参数，或调用方未传参数，也通过 Windows 启动器覆盖旧环境配置。保留原版雨课堂 main.py，不改动其心跳、网络提交或播放逻辑。
- 设置界面显示实际生效的 100% 阈值，识别旧配置并提示在下次启动或保存参数时写回本机。
- 本地执行日志里的“完成 / 跳过”只表示本轮处理终态；任务卡片改为“本轮处理结束 · 待平台核验”“本轮跳过 · 待平台核验”，不再误称服务器已完成。
- 服务器完成状态仍以雨课堂只读接口返回的可信 server_completed 标志为准；允许服务端明确标记完成但原始观看率低于 100% 的合法情况。不会篡改原始观看率。
- 增加旧阈值、参数缺省、Rust 覆盖顺序、任务状态语义等回归测试。

## 延续 rc.19 的修复
- 云端发布新版时显示更新弹窗和真实 GitHub Release 更新日志；安装后首次启动显示相应变更，离线时提供明确标记的内置说明。
- 雨课堂服务器完成标志与原始观看进度分离，支持单节只读复核与任务末尾有限次数补查。
- 保存雨课堂会话前检查课堂 ID、学校 ID，提供直达对应高级设置字段的操作。
- 保留两个平台的课程读取、原版执行器、任务恢复和课程进度展示，不以本地运行成功当作服务端学习记录。

## 构建与验收要求
- 仅在当前 main 对应版本通过 React/TypeScript、Python 回归、Windows NSIS 构建及干净安装、升级、启动、卸载 CI 后，自动创建独立预发布版本 v0.1.1-rc.20；不覆盖旧安装包。
- GitHub CI 不等于用户真实雨课堂账号验收。仍需在 Windows 上复核旧配置、课程 90%–99.9% 且 completed=0 的情况，以及服务端显式完成的情况。
- 本版本不新增自动静默安装，也不修改学习平台原版上报算法。
