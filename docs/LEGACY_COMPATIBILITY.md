# 原版功能接入与兼容性

## 迁移原则

1. 优先复用原项目代码与原版运行时；不重新实现已有的播放器、业务请求或任务执行器。
2. 原版文件作为受保护资源保留。学序适配器只负责启动、配置、状态和数据展示，不在 React 中复制业务算法。
3. 每个平台独立管理登录、参数和任务；不提供独立的通用登录页。
4. 本机运行状态、模拟片段、服务端响应和正式只读核验必须分开展示。
5. 离线测试、CI 构建和真实平台验收是不同层级，不得互相替代。

## 知到接入

| 原功能 | 学序入口 | 实际接入方式 | 验收边界 |
|---|---|---|---|
| 扫码登录 | 知到二级页面 | Tauri QR dialog + Python QR worker | 需本人 Windows 账号实测 |
| Cookie 文本/文件导入 | 知到二级页面 | 版本化 IPC → 本机 Cookie 导入器 | 不在前端 localStorage 保存凭据 |
| 官方播放器 | 知到播放模式 → 官方 WebView2 | 随安装包部署原版播放器脚本与 WebView2 资源 | 本机 HTML5 位置不代表服务器进度 |
| ZHS 原版任务 | 知到播放模式 → ZHS 0.1.5 原版任务 | sidecar 子进程调用固定版本 ZHS CLI | 保留原版执行逻辑；进程运行不等于服务器确认 |
| 课程读取 | 知到课程/进度面板 | 内置 ZHS 0.1.5 只读 CLI 与适配器 | 只接受当前会话缓存 |
| 知识点/共享课详情 | 知到课程详情 | 读取同会话课程与进度缓存 | 缺失数据不得补造 |
| 进度核验 | 知到进度面板 | 单课/全量只读查询 | 显示核验时间、stale 与 incomplete 状态 |
| 播放器退出核验 | 常驻播放器监控 | 按 run_id 识别正常退出后发起一次单课只读核验 | 不提交虚假进度 |
| 数据管理 | 知到账号与数据 | Cookie、课程缓存、WebView2 profile 分开清理 | 每个操作按明确路径执行 |

知到运行时由 Windows sidecar 打包 ZHS 0.1.5 依赖，不要求用户预先安装旧版 ZHSDesktop。旧版 WPF/安装目录仍独立保留。当前会话缓存使用 Cookie HMAC 绑定，避免把其他会话的旧缓存当作当前数据。

## 雨课堂接入

| 原功能 | 学序入口 | 实际接入方式 | 验收边界 |
|---|---|---|---|
| 会话配置 | 雨课堂二级页面 | Python adapter → Windows Credential Manager | 需本人真实会话验证 |
| 课堂/章节/视频读取 | 雨课堂登录管理 | 只读接口与章节视频元数据读取 | 真实数据需 Windows 实测 |
| 原版参数 | 雨课堂原版参数区 | 复用 `exe_entry.py` 的 `read_cfg/save_cfg`，保存原版 `.env` 配置格式；包括视频、并发、图文停留/间隔与 DEBUG 开关 | 参数通过 IPC 校验后传给子进程；DEBUG 仅写本机日志 |
| 原版任务 | 雨课堂原版任务区 | 独立 sidecar 子进程执行仓库中的 `legacy/yuketang/main.py` | 不在 UI 重写原版发送逻辑 |
| 实时运行状态 | 雨课堂原版任务区 | Tauri 子进程状态 | 进程退出不等于任务成功 |
| 进度诊断 | 雨课堂原版任务区 | 按 run_id 读取本次任务日志的数值摘要 | 本机模拟位置、日志中的服务端响应和批量统计分开展示 |

雨课堂凭据与原版任务参数分开保存：会话凭据存入 Windows Credential Manager；参数通过原版 `exe_entry.py` 的配置读写逻辑保存在学序本地配置目录；每次任务使用独立 run_id 日志目录。原版 `main.py` 不由 UI 直接导入，避免其全局日志/标准输出副作用影响 IPC 服务。

雨课堂原版参数完整映射当前 `main.py` 使用的 `VIDEO_SPEED`、`HEARTBEAT_INTERVAL`、`MAX_CONCURRENT_VIDEOS`、`COMPLETION_THRESHOLD`、`SKIP_COMPLETED`、`USE_CONCURRENT`、`TEST_MODE`、`TEST_VIDEO_COUNT`、`AUTO_RICHTEXT`、`DEBUG`、`RICHTEXT_STAY_SECONDS` 与 `RICHTEXT_SKIP_DELAY`。图文与诊断参数默认折叠；调试输出可能包含课程/视频标识，只保存在本机日志。

## 统一 UI 与运行时

- 平台登录与参数位于知到、雨课堂各自二级页面。
- 平台卡片上的“登录/管理”只折叠当前平台的登录区，不跳离平台页面。
- 侧边导航使用轻量悬浮交互，不固定占用主内容区。
- Tauri Rust 负责 sidecar 和原版任务进程管理；Python JSONL bridge 负责适配器调用。
- Windows NSIS 包含 Python sidecar、ZHS 0.1.5 运行依赖及知到官方播放器资源。
- 原版知到与雨课堂项目、旧 EXE 和旧安装目录不由学序构建/卸载流程覆盖。

## 自动化验证

Pull Request 检查包括：
- Python adapter、缓存、会话、配置和 IPC 测试；
- React 生产构建与 UI/导航/IPC 契约测试；
- Windows sidecar 冻结检查、ZHS 版本导入检查、JSONL IPC 探针和 NSIS 安装包构建。

通过 CI 只证明仓库中的自动化检查和打包流程通过，不证明学校/平台的真实账号已登录或学习进度已被认可。

## 尚需本人 Windows 真机验收

1. 干净 Windows 用户环境首次启动，阅读并确认第三方声明与隐私说明。
2. 知到扫码登录、连接诊断、课程同步、知识点/共享课详情和当前会话进度核验。
3. 官方 WebView2 播放器的打开、登录、窗口行为、关闭后单课只读核验。
4. ZHS 原版任务启动/停止与旧版 ZHSDesktop 并存，不覆盖旧数据。
5. 雨课堂会话配置、连接状态、课堂/章节/视频读取。
6. 雨课堂原版参数读取、修改、保存、重启后再读取，以及任务参数透传。
7. 两个平台的安装、升级、卸载与数据保留；核对清理按钮只清理其说明范围内的数据。

在以上真实验收完成前，不把学序描述为“真实平台端到端全部可用”。
