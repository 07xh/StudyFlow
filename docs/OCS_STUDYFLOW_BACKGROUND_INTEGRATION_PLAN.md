# StudyFlow × OCS 模块复用与后台静默任务开发计划

> 计划日期：2026-11-21  
> 项目：[`07xh/StudyFlow`](https://github.com/07xh/StudyFlow)  
> 基线：`main` / `ce5968f`（0.1.1-rc.49）  
> 性质：架构和实施计划，**非已完成功能声明**。

## 0. 用户确认的不可变目标

**StudyFlow 是唯一主程序及唯一用户界面；后台静默执行为核心目标；OCS 仅作成熟代码、算法与平台适配逻辑的参考和复用来源。**

1. **严禁引入 OCS 独立窗口、油猴浮窗或额外的 OCS 控制面板**。课程、章节、任务、日志、参数、进度和状态全部在 StudyFlow 既有 UI 内。
2. **后台执行不弹控制台窗口**。使用 StudyFlow 已随 Windows 安装包部署的 Python Sidecar/原执行器，在应用最小化或托盘常驻时继续处理允许的任务；不要求用户打开 OCS 网站、单独安装 OCS、Tampermonkey 或 ScriptCat。
3. **仅一个任务调度控制面**。复用现有 Rust ⇄ Python JSONL 桥接、任务进度、停止、暂停、恢复和服务器核验契约；不建立 OCS 专用第二套任务队列或独立 127.0.0.1 HTTP 服务。
4. **原平台能力不倒退**。知到 ZHS 原版心跳及其可用模式不因本项目改变；保留当前雨课堂、学习通、U校园的现有适配入口、课程数据和 UI；变更应向后兼容，保持原设置与课程历史。
5. **禁止伪成功**。本地请求、后台任务状态、平台回执及官方记录回读分离。只有平台确证的已完成状态可展示“已完成”；强制实际播放、验证码或人工交互的任务不能通过单纯本地计时假定完成，标注“需人工操作”。
6. **最少新增依赖、最少重写**。优先有针对性复用 OCS MIT 模块，并保留版权声明；避免以“统一架构”为由重写现有成熟业务实现。

## 1. 现状与复用范围（基于仓库代码/文档初步检查）

StudyFlow 已具备以下入口：
- `src/studyflow/services/bridge.py`：版本化 JSONL 操作分发。
- `src/studyflow/services/xuexitong_heartbeat_bridge.py`：学习通持久化运行相关服务。
- `src/studyflow/services/zhs_queue.py`：知到队列；`src/studyflow/services/legacy_playback.py`：现有执行器入口。
- `src/studyflow/platforms/{xuexitong,zhidao,yuketang,ucampus}/`：平台适配目录。
- `frontend/src/{bridge.ts,runtimeTasks.ts,progressMerge.ts,taskRecovery.tsx}`：前端桥、任务与进度整合。
- `docs/TASK_RECOVERY.md`、`docs/XUEXITONG_HEARTBEAT_INTEGRATION.md`：现有恢复/长驻桥接契约。

OCS 的研究入口（逐模块核实后再决定是否提取）：
- `ocsjs/ocsjs/packages/scripts/src/projects/cx.ts`：学习通。
- `.../zhs.ts`：知到。
- `.../yuketang.ts`：雨课堂。
- `.../icourse.ts`、`.../icve.ts`、`.../zjy.ts`：增量平台候选。
- `ocsjs/ocsjs/packages/core/src/core/`：部分可复用通用工具。
- OCS 的 DOM、油猴 API、前端 UI、浏览器播放器依赖 **不可假定能脱离页面直接静默运行**；必须逐模块判定。

原《StudyFlow → OCS 网课助手 接入分析》给出的 `bridge_http.py`、`ocs-studyflow.user.js` 与 `heartbeat.ts` 是原型资产，**不作为 StudyFlow 的正式架构或交付前置**。

## 2. 目标架构（不新增窗口）

```text
StudyFlow 现有 LightC 风格 UI
  ├─ 课程 / 章节 / 任务列表
  ├─ 启停 / 暂停 / 恢复 / 参数 / 日志
  └─ 本机执行状态 + 官方进度核验
                 │ Tauri IPC
                 ▼
        Rust 进程管理与白名单
                 │ 现有版本化 JSONL
                 ▼
        Python Sidecar / 平台执行器
          ├─ 统一的任务身份与状态契约
          ├─ 现有 ZHS / YKT / Chaoxing / U校园适配
          ├─ OCS 提取的纯解析/映射/状态辅助代码
          ├─ 会话管理与安全凭据存储
          └─ 平台只读回读 / 完成证据
```

- StudyFlow 作为**唯一可见控制面**；若任务执行需要网页参与，应仅在满足平台要求的真实学习流程中进行，不能将本地模拟事件表示为已完成学习。
- 后台任务由已打包的独立进程执行，Windows 打包配置确保无黑色控制台弹出。
- 进程寿命明确定义为“主程序运行期间/托盘常驻期间”。**退出所有程序后的独立后台服务不是本计划默认承诺**；如未来要支持，必须单独设计生命周期与退出控制。

## 3. P0 — 先做兼容性映射，不重造调度器

### P0.1 统一课程与任务身份
- 归一 `platform / account_scope / course_id / chapter_id / task_id / resource_type`。
- 所有可能超出 JavaScript 整数精度的 ID 一律保持字符串。
- 读取异常或接口空列表不应直接覆盖上一次有效课程缓存；缓存必须标记 stale，并避免展示为实时完成情况。
- 同一个资源的不同来源记录合并时，以来源、更新时间和官方核验状态作为依据，不能只取较大的百分比。

### P0.2 任务状态/互斥契约
- 保留现有平台级互斥和 ZHS 单章节多任务调度。
- 对同一个 `platform + account_scope + course_id + task_id` 建立唯一运行标识，防止旧模块与新增模块重复执行同一任务。
- 运行态建议：`queued/running/paused/waiting_for_user/failed/stopped/finished_locally/verified_complete`。
- 完成态和发送统计独立：`requests_sent`、`acknowledged`、`official_progress`、`verified_at`、`stale`。

### P0.3 OCS 代码筛选
- 首批只研究能脱离 DOM/GM API 的课程结构解析、媒体类型判断、任务标识映射、纯函数和错误状态归一。
- 使用真实输入样本做对拍；按许可证保留来源、作者、许可文本、修改说明。
- **不直接复制 OCS 整个 worker、播放器事件模拟、用户脚本外壳或任何原有功能的重复实现**。
- 若已有 StudyFlow 等价模块，就补测试或修复缺陷，不创建第二个版本。

**P0 验收：** 现有平台课程与配置保持正常；同一任务不可双重排队；后台进程无独立窗口；任务停止能回收资源；本地进度不冒充服务端完成。

## 4. P1 — 后台静默体验与进度证据

- 在既有平台界面增加/完善“后台执行”状态说明、任务队列、当前任务、可恢复快照、停止/暂停操作；仍使用统一 UI，不新建 OCS 页面。
- 最小化或托盘常驻时，后台任务连续运行；恢复主窗口后状态同步，不丢失进度与日志。
- 统一错误分类：会话失效、网络错误、平台限制、需要人工交互、资源不支持、任务已确认完成、超时/取消。
- 官方只读状态回读必须带 `verified_at`，过期结果显式标注；禁止将本机累计时间或 HTTP 200 直接变成“100% 完成”。
- 支持安全停止和合理断点恢复；不保存明文 Cookie 到任务快照；跨账号或跨课堂不自动恢复。
- 不绕过平台明确的观看、测验或验证码要求，需人工操作时显示提示并允许恢复。

**P1 验收：** UI 中操作后台任务 → 最小化 → 继续处理受支持的任务 → 还原后状态正确；停止/重启无重复任务；服务器未确认时 UI 不显示已完成。

## 5. P2 — 增量平台与功能复用

逐个平台评估 OCS 代码的可用性与服务器读取能力：
1. 学习通：先复用解析与任务分类，优先解决课程/任务覆盖不足及真实进度显示一致性。
2. 知到：保留原版 ZHS 发送链，仅补资源分类、身份/状态展示、必要的只读核验。
3. 雨课堂：优先补齐课程/视频解析、状态归一与服务器只读核验，不用 OCS 执行器替换原版。
4. 新平台（中国大学 MOOC、职教云/智慧职教等）：首先完成只读课程发现和身份契约，再评估其后台可用范围。页面强依赖场景不得承诺无页面运行。

**P2 验收：** 新接入的平台有真实可核对课程、章节和状态；未实际验收模块明确标“实验性/未验证”。

## 6. 开发顺序与交付方式

| 步骤 | 交付物 | 完成标准 |
|---|---|---|
| 1 | 代码级去重/接口差异表 | 对照 StudyFlow 和 OCS，标清“可直接复用/需包装/不采用” |
| 2 | P0 纯函数与契约补丁 | 回归测试通过；对原平台不产生调度冲突 |
| 3 | P1 后台任务体验补丁 | 最小化/托盘/启动/停止/恢复实测，无控制台及 OCS 窗口 |
| 4 | P2 平台能力增量 PR | 一个功能一组真实读取与状态证据 |
| 5 | Windows 打包与真机验收 | Python/Rust/React/NSIS CI + 真正账号的只读核验 |

开发中坚持“最小可验证改动”，不因计划完整就一次性重构全部平台；每一阶段用现有测试/CI 和明确的 Windows 手工验收表确认。

## 7. 明确不做

- 不引入独立 OCS GUI、Tampermonkey、ScriptCat 面板或额外用户脚本入口。
- 不强制本地端口 HTTP RPC 桥、不增加云服务作为启动条件。
- 不重写 ZHS 原版心跳及其他成熟执行器。
- 不将发送回执、本机播放时间、模拟进度误报为服务器已完成。
- 不为每个平台新建竞争式调度器、重复功能或相互冲突的 UI 设置。
- 不为了“静默”而绕过平台要求的人机验证、真实学习或考试规则。
