# 学序 StudyFlow 0.1.1-rc.41｜U校园已登录但无法验证课程单元修复

## 问题
用户 Windows 实机截图：U校园能展示“新视野大学英语（第四版）视听说教程 1”，但“单元与任务”显示“U校园会话已失效，请重新登录”，课程进度与任务无法核验。

## 本轮代码修复
- 课程列表和课程进度分别调用 `uai.unipus.cn` 与 `ucontent.unipus.cn`，认证证据不能混为一谈。
- 补齐 U校园 AI 浏览器公开协议中的内容侧签名认证头和 `appid`；令牌仅针对当前本机已保存 JWT 中的 openId 且仅用于官方内容接口的只读 GET。高级手动配置的内容令牌优先且不会被替换。只认官方服务器回读结果。
- 官方账号登录、二维码导入及 Cookie 手动导入统一进行可选的学校编号读取，只有合法的真实学校编号才设置 `u-school`；资料接口失败时不破坏已保存会话。
- 登录后的“验证课程读取”不再只查课程名称：真实读取至少一门课程后，针对该课程再执行一次真实的单元只读请求，分别报告两条链路的状态。
- `ucontent` 的 HTTP 401 和 403 分别显示“内容侧认证未通过”和“内容访问被拒绝”，不再误报整个 U校园 JWT 已过期；本地 JWT 确已过期时仍要求重新授权。
- 新增独立内容签名测试向量、请求头校验、401/403 状态分离、二维码会话导入及可选学校编号补齐测试。

## 不变与验收边界
- 不影响知到、雨课堂、学习通等其他平台；保留 rc.40 的二维码登录与 WebView2 可靠性修复、学序启动动画及个人账户本机存储。
- 继续仅提供**读取/核验**，不更改课程进度、不伪造学习事件、不自动申报完成。
- CI 全通过不代表本人账号的内容授权已被真实 U校园服务端接受；必须在本人 Windows 设备测试：登录 → 保存 → 查课程 → 查单元 → 查任务 → 切换课程 → 重启后复核。遇服务端 401/403 时仍应按真实返回处理，不提供虚假成功提示。
- JWT、Cookie、内容授权令牌始终不出现在前端状态、错误回包或日志中。

版本：`0.1.1-rc.41`。
