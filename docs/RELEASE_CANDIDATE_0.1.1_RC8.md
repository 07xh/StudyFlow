# 学序 0.1.1-rc.8：修复 ZHS 原版任务工作目录与退出码阶段诊断

## 实机故障
rc.6 任务曾显示：
`ZHS 已启动但原版执行失败（退出码：1）；原版主动返回非零退出状态`。
已确认 rc.6 的安全诊断无法识别 `typer.Exit(1)` 之前的关键入口阶段。

## 来源代码核查
ZHS v0.1.5 `src/zhs/utils/path.py` 用相对路径 `Path(".zhs")` 查找配置和 Cookie；
StudyFlow 只读课程及进度查询使用 `cwd=Path.home()`，但原版任务的 Rust 启动器未指定 `current_dir`。
因此当应用 CWD 不等于用户主目录时，ZHS 原版可能从错误位置恢复登录态。

另外 ZHS v0.1.5 `play()` 可能在会话预检返回 `None` 或共享课程 URL 处理异常时以代码 1 退出，之前两者都落入未知原版失败。

## rc.8 修改
- Rust 对**知到原版任务**显式使用 Tauri 用户主目录作为子进程工作目录，与现有只读进度查询路径一致。
- 对原版命令的会话预检、共享课程 URL 阶段加只读观察器，保持原来的参数、返回、异常和网络行为不变，完成后恢复原函数。
- 仅记录固定阶段代码，不保存原版输出、异常文本、Cookie、路径、服务器响应。
- Rust 本地诊断读取白名单与前端中文解释更新。
- 添加 Python、Rust、React 回归测试，包含失败分类和原函数恢复。

## 验收边界
- Python、React 浏览器布局测试、Rust/Windows NSIS 打包、清洁安装、升级、启动、卸载全部通过后才可发布。
- 需要用户真实 Windows 设备确认 ZHS 会话预检/课程读取后是否仍退出 1；打包 CI 不代表真实账号已经完成验证。
- 不修改 ZHS 上游播放/上报算法，不改变已保存 Cookie 或学习记录。
