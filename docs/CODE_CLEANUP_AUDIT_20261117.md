# 学序代码清理审计 · 2026-11-17

此文件记录经真实仓库代码检查的清理，不将“Legacy”等名称等同于无用代码。清理后均需由 CI 验证，特别是 Windows NSIS 和历史资源快照。

## 第一批：倍速与播放器运行时
- 在知到播放器设置中支持键盘输入/规范化；前端明确保存状态与非法草稿。
- Rust PowerShell / JavaScript 本地资源补丁共用锚点校验，保留历史源文件，未知或重复锚点拒绝修补。
- 移除已无使用方的忙碌状态分支，合并倍速输入框样式。
- 扩展真实历史 PowerShell 和 CRLF 回归测试。

## 第二批：设置状态
- 移除官方播放器初次读取设置的启动门禁，仍要求启动时重新读取最新持久化设置。
- 使用明确字段比较判断设置是否修改；无修改不保存。
- 合并重叠的设置网格 CSS 声明，并清除过时操作提示。

## 第三批：前端公共契约
- 查明 `LegacyPlaybackPanel`、`ZhidaoPlayerMonitor`、`ZhidaoActivityPanel` 等仍被工作台调用，予以保留。
- 知到活动日志改用共享 `ActivityEntry`，播放器关闭核验复用 `PlayerStatus` 字段类型。
- 关闭核验中的异常文本改为安全映射，并合并回调引用同步 effect。

## 第四批：课程进度数据
- 知到进度核验设置页、课程工作台、播放器关闭后回读共用 `updateZhidaoCourses`。
- 所有这些回读由 `mergeZhidaoEvidence` 合并，阻止同一会话较旧的异步服务端回读覆盖较新核验值。
- 不跨认证会话保留旧进度；较新的真实服务器数值允许下降；其他平台仍使用独立更新流程。
- 增加源码入口约束测试，避免直接覆盖课程列表的旧回调重新出现。

## 保留范围与未验收事项
- 未删除运行中的登录、课程、播放、任务、数据授权模块，未更改历史播放器源文件或平台心跳协议。
- Python、React 前端测试与 Windows 构建均需以本轮最新 SHA 的 CI 结果为准。
- Windows 真机官方播放器、课程切换、关窗后核验尚需真人实测；不能仅凭 CI 断言完整可用。

## 第五批：收拢剩余知到回读入口
- 把共享的 `updateZhidaoCourses` 移到定时核验 Hook 之前，确保初始化顺序清楚。
- 知到定时进度核验的 `onSnapshot` 与课程同步成功后的列表更新都调用该共享函数，避免各自重复执行 `mergeZhidaoEvidence`。
- 同步请求原有的会话检查、请求代次与完成提示未改动；雨课堂、学习通和 U校园继续沿用各自的平台同步逻辑。
- 新增入口与初始化顺序测试，保证后续维护不会恢复重复的课程列表更新实现。

## 第六批：全仓库调用链审查与死 UI 分支清理
- 根据 `App.tsx` 的真实调用关系确认 `PlatformCard` 有“平台总览”和“账号设置”两个在用入口，**保留两者**，不能误删总览同步与课程入口。
- 删除 `PlatformCard` 里在现有两个调用组合下不可达的旧展开标签及对应 CSS；保留完整登录设置与按钮逻辑。
- `ZhidaoActivityPanel` 在全仓库仅以 `embedded` 模式使用，删除无人调用的独立折叠面板及其 React 状态、图标与 CSS；原课程日志弹窗内容和最多 20 条记录不变。
- 平台注册表仅留实际消费的 `id/name/mark/color`；去除不用于任何界面或权限判定的 `summary` 和推测性 `capabilities` 字段，不改变后端的真实平台可用性验证。
- 新增实际 React 渲染测试，覆盖两个平台卡片入口、课程日志空状态和记录上限。
- 检查发现 `legacy/zhidao` 原始播放器与运行中的兼容路径仍被打包/调用，保留不动。
