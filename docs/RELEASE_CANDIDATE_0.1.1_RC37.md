# 学序 StudyFlow 0.1.1-rc.37｜U校园官方登录、Cookie 会话与设置布局修复

## 本版更新
- U校园5.0 / AI版增加**应用内官方 WebView2 登录窗口**。在官方页面自行完成扫码、图形验证码或其他人工验证，然后点击“完成验证，导入并验证会话”。
- Rust 原生层只读取内嵌 U校园AI 页面的 `jwt` Cookie；符合会话格式时交给本机 sidecar 保存到 Windows 凭据管理器。Cookie/JWT 不返回 React 页面，不进入日志、用户资料或 GitHub。
- 官方登录窗口只允许固定的 Unipus 第一方 HTTPS 网址；不用任何验证码绕过；官方登录完成不等于学序已获得有效会话。若未检测到 JWT，会准确提示并保留手动 Cookie 备用通道。
- 继续提供“系统浏览器登录”和原有账号密码入口。系统浏览器会话不会自动写入学序，使用手动 Cookie 导入需由本人操作。
- 解决 U校园设置窗中标签与输入框挤压、重叠；导入 Cookie 支持移除粘贴的 `Cookie:` 前缀，手动保存后自动调用真实课程目录接口，并区分目录为空、凭据失效和请求异常。

## 继承 rc.36
- 保留 rc.36 的 GitHub 公开代理下载与 SHA-256 可信断点续传。
- 保留知到、雨课堂、学习通、U校园既有课程读取、章节显示、运行参数、历史和数据存储行为；未修改上述平台的学习协议或服务器心跳。

## 验收边界
- 自动化可检查 Python、前端 UI/IPC、Rust 和 Windows NSIS 的构建与升级，但**不包含真实 U校园用户扫码登录**。
- U校园当前是否会在官方 WebView2 会话内设置适配 `uai.unipus.cn` 的 JWT、此 JWT 能否读取本人课程，仍需要本人 Windows 电脑上的实时服务器验收。
- 保存会话、HTTP 200 或空课程均不能作为真实课程或学习完成证明。未通过回读不能称为已完全接入。
- 安装包只有在主分支的 Windows CI 成功、产物发布到 `v0.1.1-rc.37` Release 后才可称为“已发布”。

版本：`0.1.1-rc.37`。
