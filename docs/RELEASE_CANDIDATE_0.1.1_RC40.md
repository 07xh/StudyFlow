# 学序 StudyFlow 0.1.1-rc.40｜U校园二维码空白和 WebView2 卡退修复

## 本版更新
- **独立二维码登录**：U校园账号密码登录继续在官方 `https://uai.unipus.cn/` 窗口完成图片/数字验证码；新“打开二维码登录”在专用的私密 WebView2 窗口访问官方 `https://sso.unipus.cn/sso/login`，可使用网站自身的“刷新二维码”功能。
- 窗口仅允许导航到明确的 Unipus 第一方 HTTPS 主机；补充经核实属于官方 QR 页资源来源的 `birdflock.unipus.cn`，不放开任意外部网站。
- 修复原生窗口创建/切换、会话保存后清理、关闭的阻塞线程执行路径，降低打开二维码时拖慢主应用的风险。WebView2 原生进程崩溃的具体根因仍需用户 Windows 事件日志才能完全排除。
- 根据当前 `ai` 或 `qr` 窗口分别读取会话 Cookie，窗口模式不混用；拒绝不受支持的模式和任意 URL。JWT/账号密码不回传 React 页面或日志。
- SSO 页面扫码成功不等于学序已获得 U校园AI JWT。会话缺失或已过期时准确报错，不会伪造课程；保留浏览器扫码及本人本机手动 Cookie 导入作为备用方案。
- 合并了 rc.39 分支中的账号图片/数字验证码提示、保存后课程只读回读及重复状态管理清理，不更改知到、雨课堂、学习通课程和任务实现。
- 前端、Rust、Python 回归测试覆盖扫码与账号模式分离、主界面不会被同步浏览器清理直接阻塞、会话保存和 JWT 不泄漏。

## 继承 rc.39
- 保留 LightC 风格启动动画、首帧主题同步、首次声明保护和其他正式发行功能。
- 保留 rc.39 已发布安装包作为独立版本，不替换历史 GitHub Release。

## 发布与真实设备验收
- 必须通过完整 Python、React、Playwright、Rust/Windows NSIS 构建及安装升级验证，再合并发布。
- CI 测试**不能**证明真实扫码二维码一定可见、扫码后获得 AI 令牌，或用户的卡退已经消失。需要在 Windows 上实际打开官方二维码窗口、验证渲染/刷新、关闭/重开、扫码登录、课程读取和应用重启。
- 如果仍闪退，仅提交脱敏 Windows 事件查看器中的故障应用、模块、异常代码与 WebView2 版本，不要提供密码、二维码令牌或 Cookie。

版本：`0.1.1-rc.40`。
