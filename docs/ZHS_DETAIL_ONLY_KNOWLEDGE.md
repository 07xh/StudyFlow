# ZHS 只有详情、无资源的智慧课程知识点

## 场景（2026-11-21 用户录屏）

在智慧课程手机端「知识点详情」页面：目录可显示该知识点，资源标签显示「暂无资源」，详情标签内存在文字与表格；「知识点最高掌握度」和目录内「已完成知识点数」是不同指标，不应互相转换。

## 本次改动

- 保留原 ZHS AI 目录与资源读取入口；对 `list_knowledge_resources` 返回空列表的知识点，新增 `detail` 类型的**非执行**队列记录。只在「全部资源」模式显示；资源类型筛选为仅视频/仅文章 PPT 时不混入。
- `detail` 记录来自真实知识点 ID、主题和名称，但它**没有资源 UID**。内部的 `resource_id=0` 仅作为不可执行的目录哨兵；它不会流入 `video_worker`、原版 ZHS 播放器或任何进度提交接口。
- 队列状态为 `informational`。Windows Rust 解码器只接受 `detail+informational` 的配对，拒绝其同时携带播放百分比、退出码或成功状态。
- 包含非执行知识点的队列退出码为 `18`（没有其他失败/中断优先级时），避免完全空跑后返回 0，让用户误以为已完成全部资源。
- 前端按章展示这种知识点，解释不能通过视频/PPT 流程处理；原版心跳协议、上报时序和所有平台配置保持不变。

## 尚未具备的能力

此截图没有提供「详情」对应的官方只读详情 API、知识点可记账操作或完整验证响应。资源目录里没有可用资源 UID，不能把标题、知识点 ID 伪装成资源 ID，也不能把「已完成 n 个」或「掌握度 0%」解释为详情内容的提交状态。

要在 StudyFlow 内完整读取详情正文，需要真实账号授权的详情只读响应与字段样例；若平台实际存在学习完成记账，还需正式接口规则和独立服务器回读证据，不能由本地退出码推定。

## 验收

- Python 离线目录模型空资源、非执行队列、退出码测试。
- Rust `detail/informational` 状态和无进度安全门禁。
- 前端类型与页面结构/提示文案检查。
- 实际知到账号对照：无资源知识点出现在目录记录，不启动发送器，不改变服务器学习进度。
