# ZHS 原生模式：只有详情、无资源的智慧课程知识点

## 需求边界

用户要在 **ZHS 内部**识别并处理知识点，不允许退回浏览器跳转或改用官方播放器。视频/PPT/文章的原版 ZHS 心跳及网络协议保持原样。

**目前仍未发现能够使无资源知识点自动增加服务器学习进度的可靠心跳**。此文件只记录已验收的只读适配及条件边界，不把页面访问日志标成完成请求。

## 两份 HAR 的证据（2026-11-21）

- 移动端目录有 147 个知识点：64 个 `studyProgress=100`，83 个 `studyProgress=0`。
- 对照桌面端 90 个无资源知识点，其中移动端显示 100% 的有 7 个，显示 0% 的有 83 个。不能把「无资源」直接等同于「必未完成」。
- 桌面端 `get-course-knowledge-dic` 提供 `resourceCount/finishedResourceCount`，移动端 `get-course-knowledge-dic-wx-three` 不提供资源数量，却提供独立的 `studyProgress`；两者不能互相代替。
- `get-map-tree-node-detail` 与 `get-map-tree-node-detail-with-mastery` 用于详情只读，`list-knowledge-resource` 可验证资源确实为空。
- `saveStudentPointLog` 在页面加载时出现。HTTP / 业务响应成功不能证明学习进度增加；两份 HAR **都未捕获 0%→100% 的进度变更**。
- 知识点使用 19 位整数 ID；Rust → JS → Python 只以十进制字符串传输，避免 JavaScript `number` 精度丢失。

## 当前实现

1. ZHS 原会话中读取知识点元数据，`zhidao.zhs.knowledge.detail` 只读展示实际返回的详情文本。
2. **桌面和移动目录均独立读取**：即使桌面目录成功，也读取移动端学习进度，而不是提前停止查询。
3. 对没有真实资源 UID 的知识点，只产生 `detail/informational` 类型的目录记录，绝不启动视频工作器。
4. 如果两个已取得的服务器学习进度均达到 100%，或仅原 ZHS 完成而移动端没有返回进度，则跳过已完成的零资源知识点；如果完成与否存在冲突，则记录 `progress_conflict`，不标记完成。
5. 官方资源数为零、资源数量与 ZHS 列表不一致、移动目录不提供资源数、目录读取失败等情况各有独立状态。所有状态均不能作为生成伪资源 ID 的理由。
6. 继续保留只读前后核验：服务器进度确实增长才显示增长，本地完成动画或正常退出不构成完成凭据。
7. **无浏览器学习入口、无模拟心跳、无虚构完成请求**，其他平台完全不受此改动影响。

## 判定和验收

- 离线 Python：双目录可读取、缺失资源数不当作零、完成状态冲突不予跳过、真实双端已完成可跳过、无资源点不启动发送器。
- Rust：`detail/informational` 不带播放百分比与成功退出码，精确传输 19 位 ID，支持 `progress_conflict`。
- React：ZHS 队列清晰解释各状态，无浏览器入口，支持只读服务器刷新。
- Windows CI 通过只是构建正确，不等于真实账号学习进度可以增加。

## 真正的心跳仍受阻于什么

官方知识图谱学生手册将知识点学习进度按其中学习资源的学习进度计算；本次样本的 83 个零资源/零进度知识点未出现可上报的真实资源。要把无资源 `detail` 从「目录提示」升级为「可执行、可上报任务」，必须先找到官方认可且**确实把同一未完成知识点的服务器进度改变**的学习操作及回读证据。严禁将 `saveStudentPointLog` 当作完成接口，也不能将局部 100% 或另一个知识点的状态套用到当前知识点。


## 新增实验性 ZHS 原生进入记录（一次性、可核验）

2026-11-21 两份 HAR 中捕获的官方网页代码，在知识点页面 `mounted()` 时调用 `saveStudentPointLog`，提交真实的 `courseId/classId/knowledgeId`；可选 `taskId` 来自路由查询。该请求在样本中成功，但样本中的知识点 **在进入之前已经是 100%**，因此不能证明此调用能增加 0% 知识点的学习进度，更不能称其为周期性心跳。

为验证用户提出的“进入观看可能就完成”这一猜测，在 ZHS **自身的详情视图**增加一个按知识点手动触发的 `zhidao.zhs.knowledge.enter`：
- 用当前登录会话严格核实知识点及“官方目录资源数确为 0、ZHS 资源列表为空、两个服务端进度口径无冲突”；证据不足则拒绝发送。
- 仅在用户点击 ZHS 内部入口时调用 **一次**官方 `saveStudentPointLog`；不打开浏览器、不模拟播放时间、不伪造资源 UID、不循环重试。与 ZHS 原版视频心跳代码完全隔离。
- 之后通过两个真实服务器目录回读，只在本知识点 `studyProgress` 有可确认变化时报告进度增长；HTTP 200 / 进入日志成功本身不等于学习完成。
- 如果未增长，返回 `unchanged` 并阻止同一运行中对该知识点的自动重复尝试。如果回读失败，返回 `verification_unavailable`，不声称完成。
- **此阶段不是全自动批量心跳**：只有真实账号在线验收能证明该事件促成进度变化，才允许考虑将它纳入自动调度；没有证据前不对一批 0% 知识点盲目连续提交。
