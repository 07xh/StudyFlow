# StudyFlow v0.1.1-rc.60｜知到掌握度章节范围与工作台升级

## 本次改进

- **可选择执行范围**：全部章节、只做一章、从开头做前 N 章、自选多个章节。使用知到只读章节目录和章节序号，不再必须处理整门课的全部知识点。任务总数、进度条、章节统计只计算本次选择的知识点。
- **暂停改为“处理完当前知识点再暂停”**：执行中点击后进入“完成当前知识点后暂停”状态；不会停在题目保存、提交或判分中间。当前知识点处理完成才变为“已暂停”，点击“继续”从下一个知识点开始。点击“取消待暂停”可在本知识点尚未处理完时取消请求。停止仍单独按安全检查点处理。
- **自动掌握度 UI 全面整理**：仅该弹窗使用更宽的二栏布局，左侧集中设置章节、答题策略、共享题库/Token、运行限制，右侧显示显眼的开始/暂停/继续/停止操作、当前知识点与轮次、总处理进度、章节进度、按需展开的知识点明细和统计。
- **避免长列表渲染卡顿**：默认不渲染 100+ 个知识点的明细 DOM，手动展开才渲染；保留状态单飞轮询、按实际状态变化更新 UI。
- **不改变知到原有提交/回读协议**：共享题库仍是可选辅助参考，官方判分结果才确定正确；不新增第二套答题引擎。

## 章节范围的边界

- 章节目录通过 `zhidao.mastery.catalog` 只读加载。没有建立试卷。
- 默认全部章节；只做一章需要选一个已知章节；自选章节至少勾选一章。没有可用目录时，受限范围不得启动。
- 执行时仍会读取服务器最新目录。若章节身份不匹配，不会猜测应处理哪一章。
- 如果此前有其他章节尚未核验的交卷，**不能通过缩小范围绕过保护**；需先确认旧交卷状态。

## 暂停语义

- `pausing`：已收到暂停请求，当前知识点继续处理直到结束，期间 UI 显示实时轮次和阶段。
- `paused`：安全知识点边界，尚未进入下一知识点。
- `resume`：从当前进程的下一待处理知识点继续。
- `stop`：按原安全检查点响应，不保证完成当前知识点。
- 应用强制退出会中断后台进程；本改动不承诺退出后能够恢复未完成试卷。

- React：章节选择发送真实章节序号、暂停中 UI、保持共享题库模式、全部旧回归。
- Windows：GitHub Actions 构建并校验 NSIS 安装、升级、启动与卸载。
